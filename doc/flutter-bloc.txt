==============================================================================
INTRODUCTION                                    *flutter-bloc-introduction*

This is a Neovim plugin for generating BLoC and Cubit boilerplate code.

==============================================================================
FEATURES                                        *flutter-bloc-features*
- Generate BLoC boilerplate code
- Generate Cubit boilerplate code
- Code actions to wrap widgets with bloc widgets

==============================================================================
INSTALLATION                                    *flutter-bloc-installation*
- With lazy.nvim:
>lua
    {
      'wa11breaker/flutter-bloc.nvim',
      opts = {},
    }
<
- With packer.nvim:
>lua
    use {
      'wa11breaker/flutter-bloc.nvim',
      config = function() require('flutter-bloc').setup() end,
    }
<
==============================================================================
CONFIGURATION                                   *flutter-bloc-configuration*

Defaults:
>lua
    require('flutter-bloc').setup({
      bloc_type = 'default',      -- 'default', 'equatable' or 'freezed'
      use_sealed_classes = false, -- 'sealed' base classes instead of 'abstract'
      enable_code_actions = true,
    })
<
==============================================================================
USAGE                                           *flutter-bloc-usage*

                                                *:FlutterCreateBloc*
:FlutterCreateBloc [dir]
                        Prompt for a name and path, then create the bloc,
                        event and state files.

                                                *:FlutterCreateCubit*
:FlutterCreateCubit [dir]
                        Prompt for a name and path, then create the cubit
                        and state files.

The name can be typed in any case (`counter`, `user_profile`, `UserProfile`).
The suggested path is `[dir]/bloc/` (or `cubit/`), where [dir] defaults to
the folder under the cursor in a file explorer, or the current file's folder.
Existing files are only overwritten after confirmation.

Example key mappings:
>lua
    vim.keymap.set("n", "<Leader>cfb", require('flutter-bloc').create_bloc,
      { desc = '[C]reate [F]lutter [B]loc' })
    vim.keymap.set("n", "<Leader>cfc", require('flutter-bloc').create_cubit,
      { desc = '[C]reate [F]lutter [C]ubit' })
<
==============================================================================
FILE EXPLORERS                                  *flutter-bloc-explorers*

Run the commands from netrw, oil.nvim, nvim-tree, neo-tree or mini.files to
create the bloc inside the folder under the cursor. The new file opens in
the editing window, not the explorer.

Other explorers can be added by filetype. The function returns the file or
folder under the cursor:
>lua
    require('flutter-bloc').setup({
      explorers = {
        ['my-explorer'] = function(bufnr)
          return require('my-explorer').get_path_under_cursor()
        end,
      },
    })
<
Or pass the folder directly:
>lua
    require('flutter-bloc').create_bloc({ dir = '/path/to/feature' })
<
==============================================================================
CODE ACTIONS                                    *flutter-bloc-code-actions*

With the cursor on a widget constructor such as `Text(...)`,
`const Text(...)` or `Foo.named(...)`, |vim.lsp.buf.code_action()| offers:

- Wrap with BlocBuilder
- Wrap with BlocSelector
- Wrap with BlocListener
- Wrap with BlocConsumer
- Wrap with BlocProvider
- Wrap with RepositoryProvider

The actions come from a small built-in language server named "flutter-bloc",
so they appear next to those from dartls. Requires the dart tree-sitter
parser. The buffer is formatted afterwards when an LSP client with
formatting is attached.
