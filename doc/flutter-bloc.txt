==============================================================================
INTRODUCTION                                    *flutter-bloc-introduction*

This is a Neovim plugin for generating BLoC and Cubit boilerplate code.

==============================================================================
FEATURES                                        *flutter-bloc-features*
- Generate BLoC boilerplate code
- Generate Cubit boilerplate code
- Code actions to wrap widgets with bloc widgets and convert to Multi* widgets
- Snippets
- Bloc lint diagnostics

==============================================================================
INSTALLATION                                    *flutter-bloc-installation*
- With lazy.nvim:
>lua
    {
      'wa11breaker/flutter-bloc.nvim',
      opts = {},
    }
<
- With packer.nvim:
>lua
    use {
      'wa11breaker/flutter-bloc.nvim',
      config = function() require('flutter-bloc').setup() end,
    }
<
==============================================================================
CONFIGURATION                                   *flutter-bloc-configuration*

Defaults:
>lua
    require('flutter-bloc').setup({
      -- 'auto' picks freezed/equatable from pubspec.yaml, else 'default'
      bloc_type = 'auto',         -- 'auto', 'default', 'equatable' or 'freezed'
      use_sealed_classes = false, -- 'sealed' base classes instead of 'abstract'
      create_directory = true,    -- create files inside a bloc/ or cubit/ folder
      -- Per-kind overrides: { type, use_sealed_classes, create_directory }
      bloc = {},
      cubit = {},
      enable_code_actions = true,
      enable_snippets = true,
      lint = {
        enabled = true,           -- only starts when the `bloc` CLI is installed
        cmd = { 'bloc', 'language-server' },
      },
    })
<
==============================================================================
USAGE                                           *flutter-bloc-usage*

                                                *:FlutterCreateBloc*
:FlutterCreateBloc [dir]
                        Prompt for a name and path, then create the bloc,
                        event and state files.

                                                *:FlutterCreateCubit*
:FlutterCreateCubit [dir]
                        Prompt for a name and path, then create the cubit
                        and state files.

The name can be typed in any case (`counter`, `user_profile`, `UserProfile`).
The suggested path is `[dir]/bloc/` (or `cubit/`, or just `[dir]/` when
`create_directory` is false), where [dir] defaults to the folder under the
cursor in a file explorer, or the current file's folder.
Existing files are only overwritten after confirmation.

Example key mappings:
>lua
    vim.keymap.set("n", "<Leader>cfb", require('flutter-bloc').create_bloc,
      { desc = '[C]reate [F]lutter [B]loc' })
    vim.keymap.set("n", "<Leader>cfc", require('flutter-bloc').create_cubit,
      { desc = '[C]reate [F]lutter [C]ubit' })
<
==============================================================================
FILE EXPLORERS                                  *flutter-bloc-explorers*

Run the commands from netrw, oil.nvim, nvim-tree, neo-tree or mini.files to
create the bloc inside the folder under the cursor. The new file opens in
the editing window, not the explorer.

Other explorers can be added by filetype. The function returns the file or
folder under the cursor:
>lua
    require('flutter-bloc').setup({
      explorers = {
        ['my-explorer'] = function(bufnr)
          return require('my-explorer').get_path_under_cursor()
        end,
      },
    })
<
Or pass the folder directly:
>lua
    require('flutter-bloc').create_bloc({ dir = '/path/to/feature' })
<
==============================================================================
CODE ACTIONS                                    *flutter-bloc-code-actions*

With the cursor on a widget constructor such as `Text(...)`,
`const Text(...)` or `Foo.named(...)`, |vim.lsp.buf.code_action()| offers:

- Convert to MultiBlocProvider / MultiBlocListener / MultiRepositoryProvider
  (on a BlocProvider, BlocListener or RepositoryProvider with a `child`;
  directly nested widgets of the same kind are merged into one list)
- Wrap with BlocBuilder
- Wrap with BlocSelector
- Wrap with BlocListener
- Wrap with BlocConsumer
- Wrap with BlocProvider
- Wrap with RepositoryProvider

Wrapping inserts a snippet (|vim.snippet|): type the bloc name, then press
<Tab> to move to the state and any other placeholders. The buffer is
formatted once the snippet is finished.

The actions come from a small built-in language server named "flutter-bloc",
so they appear next to those from dartls. Requires the dart tree-sitter
parser. Formatting uses any attached LSP client that supports it.

==============================================================================
SNIPPETS                                        *flutter-bloc-snippets*

Snippets are LSP completion items from the "flutter-bloc" language server, so
any LSP completion (blink.cmp, nvim-cmp, |lsp-completion|) offers them.

  Imports         importbloc, importflutterbloc, importbloctest
  Classes         bloc, cubit, blocstate, blocevent, blocobserver
  Handlers        onevent, _onevent
  Widgets         blocprovider, multiblocprovider, repoprovider,
                  multirepoprovider, blocbuilder, blocselector,
                  bloclistener, multibloclistener, blocconsumer
  Lookups         blocof, repoof, read, watch, select
  Tests           bloctest, mockbloc, _mockbloc, mockcubit, _mockcubit,
                  mock, _mock, fake, _fake
  Freezed         fstate, fevent

==============================================================================
LINT                                            *flutter-bloc-lint*

The bloc linter (https://bloclibrary.dev/lint/) runs as a language server
from the `bloc` CLI:
>sh
    dart pub global activate bloc_tools
<
`~/.pub-cache/bin` must be on your PATH. The server ("bloc") is started for
Dart files and `analysis_options.yaml` inside projects with a pubspec.yaml.
Rules are configured in analysis_options.yaml. Nothing runs when the CLI is
not installed.
